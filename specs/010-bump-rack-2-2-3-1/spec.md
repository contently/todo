# Slice 010 - Bump rack 2.2.2 → 2.2.3.1 and prove the suite stays green

Part of feature: **Bump rack to 2.2.3.1 (CVE-2022-30123) in contently-todo** (branch `feature/dependabot-bump-rack-to-2-2-3-1`). Kind: code. Depends on: none. Gates: none.

## What to build

Upgrade the transitive gem `rack` from 2.2.2 to the CVE-2022-30123-patched 2.2.3.1 in the only affected manifest, `contently-todo/Gemfile.lock` (line `rack (2.2.2)` → `rack (2.2.3.1)`). `rack` is NOT a direct dependency in `Gemfile`; it is required transitively by `actionpack (6.0.3.1)` (`rack (~> 2.0, >= 2.0.8)`), `rack-test (1.1.0)` (`rack (>= 1.0, < 3)`), `capybara (3.32.2)` (`rack (>= 1.6.0)`), and `sprockets (4.0.2)` (`rack (> 1, < 3)`); version 2.2.3.1 satisfies all of these, so do NOT bump Rails/actionpack or any other gem. Implementation: pin Ruby to 2.7.1 (per `Gemfile`, `.tool-versions`, and the lockfile's `RUBY VERSION 2.7.1p83` — ignore the stale `.ruby-version` of 2.5.3, which is a pre-existing quirk) and run `bundle update rack --conservative` so Bundler regenerates the lock cleanly; if the environment cannot run bundler, hand-edit only the `rack (2.2.2)` line in `Gemfile.lock` to `rack (2.2.3.1)` and leave every other line untouched. Behavior/verification: confirm `bundle lock`/`bundle check` resolves and that the diff touches only the rack line (plus, at most, a forced bundler-metadata line); then audit rack call sites — grep `app/`, `config/`, `lib/`, `config.ru` for `Rack::`, `CommonLogger`, `Rack::Lint`, and custom middleware (current survey finds NONE; Rails uses CommonLogger internally within the gem, so no app code should need changes). The patched release only adds output escaping inside Rack's own Lint/CommonLogger with no public API signature change, so no code changes are expected — but if the suite surfaces any breakage, make the minimal code change needed to keep it building and passing, and document it. Run the product's REAL test suite via run-test — both the RSpec suite (`spec/`, driven by `.rspec`) and the Rails/minitest suite (`test/`) — and confirm it passes. Tests the slice must have: rely on the existing suite as the regression guard (no new rack-specific test is required for a transitive security bump); if a fix is needed for breakage, add/adjust a test that covers it. A human verifies by: (1) `grep 'rack ' Gemfile.lock` shows `rack (2.2.3.1)`, (2) `bundle exec rspec` and the minitest suite run green, (3) the app still boots (`bundle exec rails runner 'puts Rails.application.class'` or `rails s`), and (4) the Gemfile.lock diff is limited to the rack version bump.
